# Preserve the immutable broker-independent core projection

The DEGIRO adapter reuses a reviewed broker-independent implementation through
an immutable byte projection, with provenance and propagation owned by
[CORE_PROVENANCE.md](../../CORE_PROVENANCE.md). Keep broker policy, identities,
matching, authentication and bounded transport in the adapter instead of
hand-editing the projection or extracting a shared package through changes to
the canonical sibling: independent source ownership and explicit reviewed
propagation outweigh the convenience of a jointly evolving shared module.

This records the existing architecture, not a new propagation approval. The
adapter's sequential transport binding is part of that trade-off; a new
concurrency model requires its own design rather than reusing it implicitly.

The frozen projection can drift from IBKR fixes and adapter assumptions. Byte
integrity proves fidelity to the pin, not freshness or compatibility with a new
canonical revision. The daily source watch and weekly core-integrity check expose
that drift without automatically changing code. Review relevant upstream changes
when notified and before a connector release; there is no automatic propagation
deadline. Security or correctness fixes need prompt scoped review rather than
waiting for a periodic repin.

Propagate only reviewed selected units using CORE_PROVENANCE.md, with updated
provenance, regenerated bytes and adapter regressions in one commit. Keep the
existing pin until that work passes review. A shared package or automatic main
tracking would couple release ownership and bypass this explicit compatibility
gate; the accepted cost is deliberate review and possible temporary lag.
