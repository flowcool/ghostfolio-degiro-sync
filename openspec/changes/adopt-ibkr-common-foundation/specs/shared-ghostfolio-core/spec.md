# Spec Delta

## Purpose

Keep the broker-independent Ghostfolio behavior used by DEGIRO traceable to the reviewed IBKR implementation, with reproducible byte verification and explicit adapter differences.

## ADDED Requirements

### Requirement: Reviewed multi-source projection

The canonical adoption reference SHALL be IBKR v3.0.0 commit `403b4ccf13dcce076c2dc4c08633905c96c1a898`. Provenance SHALL record ordered source paths, blob hashes and selected units, including their exact dependencies. The generator SHALL preserve each selected unit's original bytes and line endings. Generation SHALL be explicit. Verification SHALL reject altered source bytes, missing/ambiguous units, unresolved dependencies and local core edits. No automatic upstream synchronization or sibling edit is permitted.

The legacy provenance format SHALL remain readable during migration. The new format SHALL support the selected units in `ghostfolio_ibkr_sync/ghostfolio.py` and the dependency `log_lab_evidence` in `ghostfolio_ibkr_sync/ibkr.py`, plus any selected authentication dependency in `config.py`. Include annotation imports and `Config` where used. Do not import Flex fetching/parsing or sibling configuration into the DEGIRO runtime. Generated core bytes SHALL remain separate from editable adapter policy.

#### Scenario: Reproducible adopted core

- **WHEN** `.venv/bin/python scripts/check_core.py --source ../ghostfolio-ibkr-sync --check-main` runs after adoption
- **THEN** the v3.0.0 pin and selected source hashes match, every generated byte matches its deterministic projection, and later main movement is visible without changing the pin.

#### Scenario: Legacy transition and dependency failures

- **WHEN** `.venv/bin/python -m pytest -q tests/test_core_guard.py` runs legacy and multi-source fixtures, changed hashes, CRLF units, missing definitions and undeclared cross-file dependencies
- **THEN** both declared formats reconstruct their exact bytes, and every altered or incomplete projection fails closed without changing the target unless explicit generation was requested.

### Requirement: Common helpers with explicit DEGIRO safeguards

DEGIRO SHALL adopt the reviewed v3.0.0 implementations of the existing selected account, activity-eligibility, import-acceptance, uncertainty and cash helpers. The adapter SHALL account for changed signatures, including the cash base-currency argument. Reuse the common authentication protocol behind DEGIRO's stricter origin, session, timeout and credential guards.

The common foundation also includes separate read, pure-index, selection and confirmed-record interfaces. Adapt their DEGIRO behavior under `degiro-synchronization`; do not project IBKR-specific Flex parsing, position arithmetic or comment indexes into the shared byte core. The projection is one part of adoption, not its entire scope.

The adapter SHALL preserve whole-account validation, no ambient proxy/netrc/TLS overrides, secret-free diagnostics, temporary core transport/log restoration and durable uncertainty fencing. Core response-body or exception logging SHALL NOT reach operator diagnostics. Shared helpers SHALL NOT weaken account ownership, quantity proof or journal recovery. Native evidence SHALL be emitted by the adapter even when core logs are suppressed.

#### Scenario: Adapter contracts around the adopted core

- **WHEN** `.venv/bin/python -m pytest -q tests/test_ghostfolio_core.py tests/test_ghostfolio_auth.py tests/test_foundation_acceptance.py tests/test_degiro_recovery.py tests/test_foundation_evidence.py` runs
- **THEN** changed helper signatures and accepted subsets work with the real generated helpers; hostile origins, redirects, credential echoes and uncertain writes remain blocked; transport/log state restores after success and failure.

Baseline: `CORE_PROVENANCE.md`, `ghostfolio_core.py` and existing adapter regressions at DEGIRO `7751e02f90c73b0e44e67f052c715226af436aa8`; current pin `5749146ff297133a6a85d9006bba60b65d9f7cde` remains historical provenance, not the target of this adoption.
