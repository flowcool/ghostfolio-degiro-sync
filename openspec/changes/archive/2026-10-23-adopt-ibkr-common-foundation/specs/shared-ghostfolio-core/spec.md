# Spec Delta

## Purpose

Keep the broker-independent Ghostfolio behavior used by DEGIRO traceable to the reviewed IBKR implementation, with reproducible byte verification and explicit adapter differences.

## ADDED Requirements

### Requirement: Reviewed multi-source projection

The canonical adoption reference SHALL be IBKR v3.0.0 commit `403b4ccf13dcce076c2dc4c08633905c96c1a898`. Format-2 provenance SHALL record ordered source paths, SHA256 hashes of complete source-file bytes, and ordered source-qualified units. These hashes are not Git object IDs. The generator SHALL preserve each selected unit's original bytes and line endings. Generation SHALL be explicit. Verification SHALL reject altered bytes, ambiguous units, unresolved dependencies and local core edits. No automatic upstream synchronization or sibling edit is permitted.

The legacy provenance format SHALL remain readable during migration. The selected closure SHALL be exactly:

| Source | Units |
| --- | --- |
| `ghostfolio_ibkr_sync/ghostfolio.py` | Imports: `json`, `logging`, `re`, `Mapping`, `UTC`/`datetime`, `isfinite`, `Any`, `requests`, using the original complete import statements |
| Same file | Assignments: `log`, `Config`, `GHOST_REDIRECT_ERROR`, `_UNRESOLVED_SYMBOL_RE` |
| Same file | Functions: `ghost_headers`, `ghost_response_is_redirect`, `activity_date_is_current`, `activity_is_active`, `ghost_get_accounts`, `ghost_find_account_id`, `parse_unresolved_symbol`, `accepted_import_subset`, `mark_import_uncertain`, `ghost_import_activities`, `ghost_update_cash_balance` |
| `ghostfolio_ibkr_sync/ibkr.py` | Function: `log_lab_evidence` |

Order imports first, assignments second and functions third. Within each group preserve the declared source order (`ghostfolio.py`, then `ibkr.py`) and each file's line order. Use the single selected `log` assignment from `ghostfolio.py`; the evidence helper resolves to that projected logger. Do not select the second logger or duplicate imports from `ibkr.py`. Reject undeclared name collisions instead of silently choosing a definition. Statically verify globals and annotation references, including lazily evaluated Python 3.14 annotations; import success alone is insufficient. Any additional dependency requires an explicit reviewed provenance change.

Authentication and host validation SHALL stay in the private DEGIRO adapter; no `config.py`, Flex parser, `_parse_float`, `DividendContext` or sibling package import is selected. Install the root generated file as the importable `ghostfolio_core` module so isolated module execution from `/` works. Generated bytes SHALL remain separate from editable adapter policy.

#### Scenario: Reproducible adopted core

- **WHEN** `.venv/bin/python scripts/check_core.py --source ../ghostfolio-ibkr-sync --check-main` runs after adoption
- **THEN** the v3.0.0 pin and selected source hashes match, every generated byte matches its deterministic projection, and later main movement is visible without changing the pin.

#### Scenario: Legacy transition and dependency failures

- **WHEN** `.venv/bin/python -m pytest -q tests/test_core_guard.py` runs legacy and multi-source fixtures, changed hashes, CRLF units, collisions, import order, missing globals and lazy annotation dependencies
- **THEN** both formats reconstruct exact bytes, the selected closure imports and resolves annotations, and altered or incomplete projections fail closed without changing the target unless generation was explicit.

The `--source` verification command reads Git objects without changing the sibling. Propagation/regeneration SHALL use a disposable Git checkout containing the pin, as required by `CORE_PROVENANCE.md`; an exported archive alone is not a Git source.

### Requirement: Common helpers with explicit DEGIRO safeguards

DEGIRO SHALL adopt the reviewed v3.0.0 implementations of the selected account, activity-eligibility, import-acceptance, uncertainty and cash helpers. The adapter SHALL account for changed signatures, including cash base currency. Preserve the common authentication protocol through DEGIRO's existing private session, exactly one token exchange, strict origin, no redirects and credential guards. Do not route authentication through the sync transport or the upstream global `requests.post` helper.

The common foundation also includes separate read, pure-index, selection and confirmed-record interfaces. Adapt their DEGIRO behavior under `degiro-synchronization`; do not project IBKR-specific Flex parsing, position arithmetic or comment indexes into the shared byte core. The projection is one part of adoption, not its entire scope.

The adapter SHALL preserve whole-account validation, no ambient proxy/netrc/TLS overrides, secret-free diagnostics, temporary core transport/log restoration and durable uncertainty fencing. Apply explicit bounded per-operation timeouts; the current blanket 60-second override SHALL NOT replace account-read or cash-write timeouts. Core response-body or exception logging SHALL NOT reach operator diagnostics. Shared helpers SHALL NOT weaken ownership, quantity proof or recovery. Keep core logs suppressed during binding and emit each native evidence record exactly once through the adapter.

#### Scenario: Adapter contracts around the adopted core

- **WHEN** `.venv/bin/python -m pytest -q tests/test_ghostfolio_core.py tests/test_ghostfolio_auth.py tests/test_foundation_acceptance.py tests/test_degiro_recovery.py tests/test_foundation_evidence.py` runs
- **THEN** changed helper signatures and accepted subsets work with the real generated helpers; hostile origins, redirects, credential echoes and uncertain writes remain blocked; transport/log state restores after success and failure.

Baseline: `CORE_PROVENANCE.md`, `ghostfolio_core.py` and existing adapter regressions at DEGIRO `7751e02f90c73b0e44e67f052c715226af436aa8`; current pin `5749146ff297133a6a85d9006bba60b65d9f7cde` remains historical provenance, not the target of this adoption.
